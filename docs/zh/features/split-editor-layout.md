# 分屏编辑布局

## 概述

编辑 / 分屏 / 预览三种视图模式，可拖拽、可键盘到达的分割条，手机宽度
强制转换，以及比例式双向滚动同步——表达为 `<body>` 上的 `data-mode`
属性，由 CSS 按断点解析。

## 背景

核心体验是「左写右读」。这需要一个在桌面宽度、平板、手机、横竖屏之间
保持正确的布局系统，还要照顾一个必须在窗格尺寸或可见性变化后重新测量
的代码编辑器（CodeMirror）。

## 问题

1. 分屏需要用户可调的比例，且鼠标、触屏、键盘都可发现、可操作，钳制在
   合理边界内，并可持久化。
2. 手机宽度下并排分屏不可用——模式必须降级，同时不丢用户的桌面偏好。
3. 编辑器与预览必须*按比例*（而非按行）双向联动滚动，且不能形成反馈
   循环。
4. CodeMirror 在隐藏或被调整尺寸的容器中测量会失准；出错时表现为叠行
   或空白窗格。

## 目标

- 三种模式、一个事实来源，无需刷新即时切换。
- 分割条：拖拽（pointer 事件）、方向键（±2%）、双击复位、钳制
  25%–75%、末次调整约 300ms 后持久化。
- 手机（≤767px）：`split` 强制转为 `edit`；分屏按钮隐藏；桌面偏好
  保留。
- 滚动同步：比例式、双向、可开关、无循环风险。
- 模式切换、分割条释放、窗口 resize 时 CodeMirror 测量不出错。

## 非目标（Non-Goals）

- 不做多窗格（3+）布局，不提供纵向堆叠选项。
- 不做按文档记忆布局——模式与比例是应用级偏好。
- 手机上不做可拖拽的预览宽度把手（用单窗格标签替代）。
- 同步开启时不保留各窗格独立滚动位置；关闭同步即是出口。
- 不做布局动画；变化即时生效是刻意设计。

## 方案概览

模式存放于 `<body data-mode>`；CSS 按媒体查询决定窗格可见性——
JavaScript 只翻转属性。请求的模式原样存储；*生效*模式经计算得出
（`effectiveMode`）：手机视口下 `split` 变 `edit`，非法值回退 `split`。
分割条是 `role="separator"` 元素，拖拽期间 pointer capture，把比例写入
CSS 自定义属性 `--split` 并（防抖后）持久化到 `mdpress-split`。滚动
同步监听两个滚动容器，映射滚动*比例*（而非像素），每次程序化滚动后
锁定 120ms 防止乒乓。`matchMedia('(max-width: 767px)')` 的 change 事件
与窗口 resize 都会重新应用生效模式；CSS 手机规则是事件失效时的兜底。

## 详细行为

- 模式切换：设置属性、更新三个按钮的 `aria-pressed`、持久化、通知
  监听者。CodeMirror 在下一 tick 刷新，因为它可能刚从隐藏中恢复。
- 分割条拖拽：分割条上 pointer capture；body 获得类 `col-resizing`
  （禁选文本、列调整光标）。拖拽把指针 X 映射为相对工作区的百分比。
- 键盘：分割条聚焦时 `←`/`→` 每次调整 2 个百分点；双击复位 50。
  分割条的 aria-label 说明了这些操作。
- 滚动同步：ratio = scrollTop / 可滚动高度，映射到另一窗格的可滚动
  范围；仅在分屏模式且开启时生效；「滚动同步」开关翻转 `aria-pressed`
  并立即生效。
- 手机强制：存储中的请求模式保持 `split`；下一次媒体查询求值时放大
  窗口即自动恢复分屏。
- 已知时序：模式切换、分割条释放与窗口 resize 都会调度
  `editor.refresh()`（0–50ms）以强制 CodeMirror 重新测量。

## 兼容性与历史影响

随初始版本发布。手机强制转换（768px 以下 split → edit 且保留存储偏好）
与滚动同步锁属于打首个 Tag 前的打磨；本功能之外不影响任何历史行为。

## 数据与隐私影响

在 `localStorage` 中引入 `mdpress-mode` 与 `mdpress-split`——仅偏好
数据，不含 `mdpress-doc` 之外的文档内容。

## 性能影响

滚动同步每事件 O(1)，120ms 锁防乒乓；模式切换是属性翻转加一次
CodeMirror 刷新。不发布测量数据。

## 当前限制

- 比例粒度为整数百分点。
- 编辑与预览模式下分割条不可拖拽（按定义只有一个窗格可见）。
- 同步映射的是滚动*比例*而非元素位置：矮文档配高窗格时在两端可能
  轻微漂移。
