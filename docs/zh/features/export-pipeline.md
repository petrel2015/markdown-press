# 导出管线

## 概述

四条本地导出路径——经浏览器打印对话框的 A4 PDF、2× 像素比的手机长图与
A4 宽度 PNG、以及 `.md` 源文件的下载/打开——全部在浏览器内生成，文件名
由文档名驱动。

## 背景

Markdown 编辑器只有当输出能以他人可消费的形式离开浏览器时才有用。
Markdown 源文件服务技术读者；PDF 与图片服务所有人。实时预览从项目之初
就有；设计工作在于让每条导出忠实、确定性强且依赖极轻。

## 问题

1. **PDF**：在浏览器中产出真正的 PDF 通常意味着重量级库（pdfkit/jsPDF
   + 布局重实现）或服务器——两者都违背零依赖、零后端约束。
2. **图片**：「手机可读」的长图与分页的 A4 图像必须从*渲染后*的文档
   栅格化——包括图表——宽度可控、白底、像素比足够锐利。
3. **往返**：用户也需要拿回源文件——保存它，之后再次打开而不丢数据。

## 目标

- PDF 保持矢量、可选文字；图表为原生 SVG；不新增依赖。
- PNG 导出为固定逻辑宽度（390px 手机、794px A4）× 2 设备像素比、白底、
  文件名派生自文档名。
- `.md` 下载与打开，带扩展名校验与跨平台文件名净化。
- 四条路径全部离线可用。

## 非目标（Non-Goals）

- 不做服务端渲染或无头浏览器 PDF；浏览器打印对话框就是 PDF 引擎。
- 除打印对话框提供的选项外不做分页控制 UI；边距与页面尺寸跟随浏览器
  与 `@page` 规则。
- 不做 PDF 专属主题——打印样式表是固定的 A4 纸。
- 不导出编辑器窗格；导出总是从源文本重新渲染。
- 不提供图片格式选项（JPEG/WebP）；只有 PNG，且固定 2×。

## 方案概览

- **打印**：实时预览的 HTML 克隆进 `#print-root` 容器；
  `document.title` 临时换成文档名（成为建议的 PDF 文件名）；
  `window.print()` 在 `requestAnimationFrame` 内执行。
  `css/print.css` 将克隆内容排为 A4 纸并防止块被截断。`afterprint`
  还原标题并清空容器；60s 定时器为从不触发 `afterprint` 的浏览器兜底。
- **PNG**：隐藏的 `#png-root` 容器设为规格宽度；源文本经一次全新
  `marked.parse` 填入；图表在其中重渲；等待全部 `<img>`（每张上限 4s）；
  `html-to-image.toPng` 以 `pixelRatio: 2` 在白底栅格化；data URL 以
  `<名称>-phone.png` 或 `<名称>-a4.png` 下载。
- **.md**：`Blob` + object URL + `a[download]`，1s 后回收。**打开**：
  隐藏的文件输入接受 `.md`/`.markdown`/`.txt`；`FileReader` 本地读取；
  文件名（净化、去扩展名）成为文档名。

## 详细行为

| 路径 | 输出文件名 | 尺寸 / 说明 |
|------|------------|-------------|
| A4 PDF（打印） | `<名称>.pdf`（由标题建议） | `@page` 规定的 A4 页；矢量文字 |
| 手机 PNG | `<名称>-phone.png` | 390px 逻辑 × 2 = 780px 宽，20px 内边距 |
| A4 PNG | `<名称>-a4.png` | 794px 逻辑 × 2 = 1588px 宽，60px 内边距 |
| `.md` 下载 | `<名称>.md` | 原样输出源文本 |
| 打开 | — | 替换当前文档；立即自动保存 |

文件名规则：文档基础名被净化（`\ / : * ? " < > |` → `_`，空白折叠）；
下载时缺 `.md` 后缀则补上；打开时拒绝其他扩展名并给出本地化提示。

PNG 运行期间状态栏显示「正在生成图片…」，成功显示「已导出」，失败显示
「导出失败——详情见控制台。」（各自 4s 后消失）。PNG 失败不会在
`#png-root` 留下内容。

被 CORS 拦截的远程图片会从 PNG 输出中排除（画布读不到其像素）；本地与
data-URI 图片会被等待并包含。

## 用户体验

![导出菜单与三个导出目标](../../img/export-menu-en.webp)

一个菜单三个导出目标，旁边是 `.md` 按钮。PDF 的体验就像打印（因为它
确实是），这也正是其文字保持可选的原因。

## 兼容性与历史影响

四条路径随初始版本发布。「不影响任何历史行为」——不存在需要保持兼容的
更早导出格式。`.md` 的打开/保存契约（扩展名集合、净化规则）是面向未来
的稳定接口。

## 数据与隐私影响

所有导出均在本地生成并下载；不上传任何内容，也不引入新的存储键。文件
选择器只读取用户选中的文件。object URL 用后即回收。

## 性能影响

PNG 导出成本随文档长度增长（完整重解析 + 2× 栅格化）；图片等待每张上限
4s。不发布测量数据。

## 当前限制

- PDF 导出内的分页由浏览器在 `@page` 规则内控制；无法逐页微调。
- PNG 是唯一栅格格式且固定 2×。
- 被 CORS 锁定的远程图片会从 PNG 中消失（见
  [故障排查](../troubleshooting.md#远程图片未出现在-png-导出中)）。
- 超大文档可能在栅格化时耗尽内存——表现为标准的导出失败提示。
