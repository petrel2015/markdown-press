# 中英文界面

## 概述

整个 UI——文案、ARIA 字符串、页面标题、错误提示与首启动示例文档——均有
English 与 简体中文 两份，带浏览器语言检测、手动切换与持久化。

## 背景

Markdown 的重心在英文，但本工具相当一部分受众用中文写作；CJK 文本同时
改变了字数统计的语义。首帧即双语——而非机器翻译的帮助文本——是立项时
的要求。

## 问题

1. 首次访问必须以用户的语言落地，无需寻找设置。
2. 切换必须瞬时重标一切——包括 ARIA 标签与 `<title>`——且不刷新、不
   重渲文档。
3. 提示（导出失败、文件被拒、启动错误）由非 UI 模块产生，因此字符串
   查询必须在任何模块可用，而不只在静态标记里。
4. 首启动展示的示例文档应当以用户的语言教学，中文版引用块若用英文会
   显得生硬，应就地中文化。

## 目标

- 按已存选择 → 浏览器语言 → 英文 的顺序检测语言。
- 每种语言一份字典；所有用户可见字符串都出自它。
- 切换零闪烁、不触发文档重渲。
- 语言选择持久化，并在之后的访问中优先于检测。
- 状态栏按 CJK 语义统计字数（每个中文字符 = 1 词）。

## 非目标（Non-Goals）

- 不超过两种语言——字典是人工维护的；加入第三种是刻意的未来决策，
  不是缺口。
- 除状态栏的固定格式外，不做本地化日期/数字格式化。
- 不翻译*用户内容*——只翻译界面与示例文档。
- 不支持从右到左布局。
- 不做地区变体（en-GB、zh-TW）；`zh*` 匹配 → zh，`en*` 匹配 → en。

## 方案概览

`MD.i18n` 在单一结构中持有两份字典，暴露带 `{n}` 风格插值的
`t(key, params)`。静态标记声明 `data-i18n`、`data-i18n-aria-label`
属性；`apply()` 遍历它们，同时改写 `<title>` 与 `<html lang>`。动态
字符串在渲染时调用 `t()`（状态栏、提示、mermaid 错误标签、示例文档）。
检测顺序：`localStorage['mdpress-lang']` 合法则用之 → 首个匹配 `zh*`
或 `en*` 的浏览器语言 → `en`。顶栏开关调用 `setLang`，后者持久化并通知
监听者（应用重绘按压态、统计与保存标签）。

## 详细行为

- 未知键回退英文字典，再回退键名本身。
- 语言按钮以 `aria-pressed` 反映当前语言。
- 示例文档取自当前字典——切换语言*不会*替换用户当前文档；只改变
  首启动将展示的内容。
- 存储失败（隐私模式）降级为内存中的语言选择。
- `html lang` 变为 `zh-CN` 或 `en`，帮助读屏器并统一编辑器的拼写检查
  行为（编辑器本身始终 `spellcheck=false`）。

## 用户体验

EN / 中文 一对按钮位于顶栏右上方。一次点击翻转所有文案；红色下划线的
活动标记随之移动；页面标题与状态栏同步跟随。无刷新，光标位置不丢。

## 兼容性与历史影响

随初始版本发布。「不影响任何历史行为」——从首个提交起语言处理就是
字典制的。

## 数据与隐私影响

一个 `localStorage` 键：`mdpress-lang`（取值 `en` 或 `zh`）。无网络、
无新权限。

## 性能影响

字典查询是普通对象读取；`apply()` 在切换时对带属性元素做一次
`querySelectorAll`。可忽略；不发布测量数据。

## 当前限制

- 机器翻译质量风险以人工维护两份字典的方式控制；若新字符串只加入其
  中一份，两者可能漂移。
- `prompt()`/`confirm()` 对话框的消息文本已翻译，但浏览器自带的按钮
  （OK/Cancel）以浏览器语言呈现，而非应用语言。
