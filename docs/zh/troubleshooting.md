# 故障排查

MD·PRESS 真实的故障模式——症状、排查顺序、修复动作与兜底。每一条都对应
代码中被守卫的路径（见[架构](./architecture.md)）。English:
[troubleshooting](../en/troubleshooting.md)。

## 速查表

| 症状 | 最可能原因 | 修复 |
|------|------------|------|
| 图表显示为原码 | 页面经 `file://` 打开 | 改用 `http(s)` 伺服（见下） |
| "图表语法错误"标签 | Mermaid 语法非法 | 修正围栏内的语法 |
| "导出失败——详情见控制台。" | html-to-image 缺失或栅格化抛错 | 刷新页面；查看控制台细节 |
| 远程图片未出现在 PNG 中 | 被 CORS 拦截 | 图片本地化或改用 data URI |
| "仅支持 .md、.markdown 或 .txt 文件。" | `打开 .md` 文件类型不对 | 使用受支持的扩展名 |
| "无法读取该文件。" | 文件不可读 | 重新选择文件 |
| "部分功能启动失败——请刷新页面重试。" | 某启动阶段抛错 | 刷新；若复现，查控制台 |
| 清除站点数据后文档丢失 | 唯一副本在 `localStorage` | 用 下载 .md 保留外部副本 |
| 旋转或 resize 后编辑器错位/叠行 | CodeMirror 需要刷新（通常自动） | 切换一次视图模式，或再次调整窗口 |

## 图表显示为源码

**症状**——` ```mermaid ` 围栏显示为代码块，无图表；其余 Markdown 渲染
正常。

**原因**——mermaid bundle 不随页面预载，而是按需注入，注入器在页面协议
非 `http(s)` 时有意拒绝运行。直接打开 `index.html`（URL 以 `file://`
开头）因此保留原码。这是设计行为，不是 bug。

**修复**——以 HTTP 伺服该目录：

```sh
python3 -m http.server 8765
# → http://localhost:8765/
```

**http(s) 下仍不渲染**——打开浏览器控制台：`vendor/mermaid.min.js`
请求失败（404、被拦截）意味着文件缺失，或浏览器扩展/安全软件拦截了它；
应用会以原码形态继续工作。

## 图表语法错误标签

**症状**——图表原码上方出现红色"图表语法错误"标签。

**原因**——mermaid 拒绝了该图表。失败被隔离：预览其余部分不受影响，
修正语法后即重新渲染。

**修复**——检查围栏内容：语句顺序、括号失衡、mermaid 10.9.3 不支持的
图表类型。该标签是设计好的错误呈现（见
[功能设计/Mermaid 图表](./features/mermaid-diagrams.md)）。

## 导出失败

**症状**——状态栏显示"导出失败——详情见控制台。"，没有文件下载。

**排查顺序**——

1. 控制台：`html-to-image` 加载失败（`vendor/html-to-image.min.js`
   请求报错）→ PNG 导出无法运行；PDF/打印与 `.md` 不依赖它。
2. 控制台中栅格化抛错（超大文档可能耗尽内存）→ 改导出较短文档，或
   走 A4 PDF 路径。
3. 文档本身：始终无法解析的图片会让导出每张最多等 4s，并可能中止本次
   导出。

## 远程图片未出现在 PNG 导出中

**症状**——PNG 导出成功，但来自其他域名的图片缺失。

**原因**——画布栅格化无法读取被 CORS 拦截的远程图片像素；
`html-to-image` 将其排除。

**修复**——引用本地文件或 data URI。PDF/打印不受影响（打印管线不基于
画布）。

## 文件打开被拒绝

**症状**——提示"仅支持 .md、.markdown 或 .txt 文件。"。

**原因/修复**——选择器的扩展名检查是严格的；重命名文件，或直接粘贴
内容。若合法 `.md` 被拒，检查是否存在隐藏的双重扩展名。

## 启动错误提示

**症状**——状态栏显示"部分功能启动失败——请刷新页面重试。"；部分控件
可能仍可用（启动阶段相互容错隔离）。

**排查**——控制台中以 `MD·PRESS boot:` 为前缀的行会指出失败阶段。先
刷新。若在 http(s) 下普通刷新仍复现，请带着该控制台行、浏览器与版本
提 Issue。

## 文档丢失

**症状**——文档为空，或重置为示例。

**原因**——唯一副本在 `localStorage`；清除站点数据、隐私模式或存储配额
压力都会使其消失。有意不设服务器副本。

**预防**——重要的内容用 `下载 .md` 留存。只有当存储中完全没有文档时
才会重新出现示例文档。

## 调整窗口后布局异常

**症状**——平板旋转或跨越手机断点调整窗口后，编辑器行叠错或窗格内容
陈旧。

**原因**——CodeMirror 在窗格尺寸或可见性变化后必须重新测量；应用已在
模式切换、分割条释放与窗口 resize 时调度刷新，但个别事件序列可能漏掉。

**修复**——切换一次 编辑/分屏/预览，或轻微再调整窗口。若某个特定操作
序列能稳定复现，那是 bug——请报告该序列。

## 仍未解决？

到 <https://github.com/petrel2015/markdown-press/issues> 提 Issue，附上：

1. 你做了什么、期望什么。
2. 浏览器名称/版本与 URL 方案（`http(s)://` 还是 `file://`）。
3. 控制台输出（尤其是 `MD·PRESS boot:` 前缀的行）。
4. 问题是否在在线 Demo 上复现——这能区分应用缺陷与本地伺服问题。
